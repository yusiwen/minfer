# minfer Compute Graph Architecture Rewrite Plan

Rewrite minfer from imperative forward pass to declarative compute graph architecture, targeting llama.cpp's `ggml_cgraph` + backend scheduler design.

> 修订记录（2026-08）：依据对 llama.cpp HEAD `749f688fc` 的逐行核对修正：
> 1. **KV cache 位置数据化**——`n_past` 不再进入图 IR（原方案把 `n_past` 编入 `KvcacheLoad`，会导致 decode 每步拓扑变化、图复用结构性失效）；KV cache 改为持久外部缓冲，位置经输入节点注入（llama.cpp 的 `allow_reuse` 不比较 `n_past`）。
> 2. **复用判定改为参数确定性**——不再"先建图后比较"（原方案 `try_reuse(new_graph)` 跳过不了重建），也不再用 `mem::discriminant` 只比变体（会漏比 `transpose_b`/`eps`/`weight_name` 等负载）；仿 `llm_graph_params::allow_reuse` 只比较参数。
> 3. **Backend 抽象设备化**——原 `execute_node(&[&[f32]] -> &mut [f32])` 是纯 CPU slice 接口，Metal 落地要么每节点 host 往返、要么 trait 失真；改为后端自有缓冲池 + buffer id。
> 4. **修正现状描述**——minfer 已存在大量手工融合（GPU `swiglu_f32`/`attn_bias_rope_store`/融合 qkv+gu kernel、批量 matmul 共享量化），本方案是"把融合显式化"，不是"从无到有"；CUDA 包装现有 `cuda.rs`（含 CUDA Graph），**不是 stub**。

---

## 1. Design Goals

| Goal | Current State | Target State |
|------|---------------|--------------|
| Multi-backend dispatch | forward.rs hardcodes GPU/CPU paths | Backend assigned per op at graph build time, auto partition |
| Operator fusion | **手工融合已存在**：GPU `swiglu_f32`、`attn_bias_rope_store`（add_bias×3+rope×2+store_kv×2 → 1 dispatch）、`blk.attn_qkv`/`ffn_gu` 融合权重、批量 matmul 共享量化（Q4_0）；CPU 批量 matmul 但**逐 matmul 重新量化** | 融合成为 IR 一等公民（`SwiGLU`/`FusedBiasRope`/`BatchMatMul`），由 pattern matching 生成、按后端能力（`supports_fused`）分发，可组合可移植 |
| Graph reuse | 每步重推拓扑 + CPU scratch 重新分配（GPU 缓冲已由 `get_or_grow` 池跨调用复用） | 参数确定性复用：同拓扑图跳过重建与分配，只更新输入数据 |
| Extensibility | New models require rewriting entire forward.rs (~620 lines) | New models only need graph construction (~200 lines), reuse all infrastructure |
| GPU fallback | Runtime `layer_gpu()` returns false to fallback to CPU | Backend decided at graph build time based on weight registration status（**保留 GPU_SAFETY.md 区分：guard 失败 → `gpu_abort`；仅支持性限制 → 回退**） |
| CUDA | 已有 `cuda.rs`（`layer_gpu` + CUDA Graph 捕获/回放，feature-gated） | 包装为 `CudaBackend`，保留 CUDA Graph（以图 `uid` 为键）——**不是 stub** |

## 2. Overall Architecture

```
                  ┌──────────────────────────────────┐
                  │       GraphBuilder (per arch)      │
                  │  Builds ComputeGraph (declarative IR)│
                  └──────────┬───────────────────────┘
                             │ ComputeGraph
                             ▼
                  ┌──────────────────────────────────┐
                  │       BackendScheduler             │
                  │  1. assign_backend(): per op → GPU/CPU │
                  │  2. fuse(): fusion pass (capability-driven) │
                  │  3. split_graph(): partition into subgraphs │
                  │  4. allocate(): per-backend buffer alloc+reuse │
                  └──────────┬───────────────────────┘
                             │
                ┌────────────┼────────────┐
                ▼            ▼            ▼
          ┌──────────┐ ┌──────────┐ ┌──────────┐
          │ CpuBackend│ │MetalBack │ │CudaBackend│
          │(kernel.rs)│ │(mps op)  │ │(cuda.rs) │
          └──────────┘ └──────────┘ └──────────┘
```

调度器策略（新增，来自 llama.cpp 行为核对）：

- **attention 与 KV cache 强制同后端**——避免跨后端 KV 拷贝（每步 O(nkv) 的 GPU↔CPU 回传是 minfer 当前刻意避免的 "KV-growth decode 成本"）。
- **同一 split 内的 GPU op 共享一条 command buffer**，仅在 split 边界提交（现状 forward.rs 已是全模型单 cb，需在 scheduler 中保持并形式化）。
- **融合由 backend `supports_fused` 驱动**——不强制融合，避免与现有融合 kernel 双重融合。

## 3. Core Data Structures

### 3.1 Compute Graph IR (`src/graph/mod.rs`)

```rust
pub type NodeId = usize;

#[derive(Clone, Copy, PartialEq, Eq, Debug)]
pub enum DType { F32, F16, I32, Q8_0 }

/// Operator type
#[derive(Clone, PartialEq, Debug)] // PartialEq: 完整比较负载（含 transpose_b/eps 等），
                                   // 供 debug 构建的复用一致性校验；正式复用判定走参数比较
pub enum Op {
    // Element-wise
    Add,
    Mul,
    Scale(f32),
    Silu,

    // Reduction
    Softmax { dim: usize },

    // Normalization
    RmsNorm { eps: f32 },

    // Linear algebra
    MatMul { transpose_b: bool },

    // Indexing
    GetRows,  // embedding lookup / 行选择（也用于 n_out 尾部行，见 §5.5）

    // Positional encoding
    RoPE { style: RopeStyle },

    // Attention
    Attn { mode: AttnMode },

    // KV Cache —— 持久外部缓冲 + 位置数据注入，n_past 不进入 IR
    KvcacheStore { layer: usize },  // 把本步 k/v 写入 persistent KV 区（写入位置来自 positions 输入）
    KvcacheLoad { layer: usize },   // 读取历史 KV（persistent KV 区的视图），拓扑与 n_past 无关

    // View/reshape
    View { offset: usize, shape: [usize; 4] },
    Reshape { shape: [usize; 4] },
    Permute { dims: [usize; 4] },

    // Fused ops (generated by fusion pass, gated by backend supports_fused)
    SwiGLU,            // silu(gate) * up —— GPU 已有 kernel_swiglu_f32；CPU 需新 kernel 或执行期分解
    FusedBiasRope,     // add_bias + rope —— GPU 已有 attn_bias_rope_store（还合并了 store_kv）
    BatchMatMul,       // multiple matmuls sharing input —— GPU 已有（Q4_0 共享量化），CPU 需共享量化
}

#[derive(Clone, Copy, PartialEq, Eq, Debug)]
pub enum AttnMode { Mha, Gqa, Flash }

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Backend { CPU, Metal, Cuda }

/// Single compute node
pub struct CNode {
    pub id: NodeId,
    pub name: String,
    pub op: Op,
    pub src: Vec<NodeId>,        // input dependencies
    pub out_shape: [usize; 4],   // output shape
    pub out_dtype: DType,        // output data type
    pub backend: Option<Backend>, // None = decided by scheduler
    pub meta: Box<dyn Any + Send + Sync>, // op-specific metadata
}

/// Op metadata types
pub struct MatMulMeta { pub weight_name: String, pub bias_name: Option<String> }
pub struct RoPEMeta { pub freq_base: f32, pub freq_scale: f32 }
pub struct AttnMeta { pub n_head: usize, pub n_head_kv: usize, pub hd: usize, pub hd_kv: usize }
pub struct KvcacheMeta { pub n_embd: usize, pub n_head_kv: usize }
pub struct EmbedMeta { pub vocab_size: usize }

/// Compute graph
pub struct ComputeGraph {
    pub nodes: Vec<CNode>,
    pub inputs: Vec<NodeId>,     // input nodes that need external filling
    pub outputs: Vec<NodeId>,    // output nodes (logits, etc.)
    pub uid: u64,                // graph identifier，供 CUDA Graph 缓存等复用检测
    pub persistent: Vec<PersistentBuf>, // KV cache 等常驻缓冲描述（实际存储归 allocator）
}
```

**KV cache 的关键约定（修正项）**：`KvcacheStore`/`KvcacheLoad` 不携带任何位置信息。KV 数据区由 allocator 以 `alloc_persistent` 分配（每层一块，形状 = `[n_embd, n_ctx]`，GPU 路径为 MTLBuffer 池内常驻段），图节点只声明"第 `layer` 层的读写"。每步的写入位置 = `positions` 输入节点的值（与当前 forward.rs `store_multi(positions, …)` 语义一致）。因此**图拓扑不随 KV 长度变化**——这是 decode 图复用的前提，与 llama.cpp `allow_reuse()` 不比较 `n_past` 的行为一致。

### 3.3 Memory Allocator (`src/graph/alloc.rs`)

按后端分池（修正项：不再只有 `Vec<f32>`；Metal/CUDA 池各自持有设备缓冲，等价于 llama.cpp `ggml_gallocr` 的 per-backend 缓冲池）：

```rust
/// 缓冲句柄：backend + 该后端池内的 id
#[derive(Clone, Copy, PartialEq, Eq, Debug)]
pub struct BufRef { pub backend: Backend, pub id: usize }

pub struct GraphAllocator {
    cpu: CpuBufferPool,                       // Vec<f32> 分段池（liveness 复用）
    #[cfg(target_os = "macos")]
    metal: MetalBufferPool,                   // MTLBuffer 分段池（移植 get_or_grow）
    #[cfg(feature = "cuda")]
    cuda: CudaBufferPool,                     // 移植 cuda.rs 缓冲管理
    node_to_buf: HashMap<NodeId, BufRef>,
    persistent: Vec<PersistentBuf>,           // KV cache 等常驻区（跨步骤存活）
}

pub struct PersistentBuf { pub name: String, pub backend: Backend, pub id: usize }

impl GraphAllocator {
    /// liveness analysis + per-backend buffer allocation
    pub fn alloc_graph(&mut self, graph: &ComputeGraph) {
        // 1. topological sort
        let order = graph.topo_order();
        // 2. compute liveness interval [start, end) for each node
        let liveness = self.compute_liveness(&order, graph);
        // 3. greedy allocation: nodes with non-overlapping liveness share segments
        //    分配按节点 backend（assign 后）落到对应后端池
        for node_id in &order {
            let buf_size = graph.nodes[*node_id].out_shape.iter().product::<usize>();
            let backend = graph.nodes[*node_id].backend.unwrap();
            let buf_id = self.find_reusable_buffer(backend, buf_size, &liveness, *node_id);
            self.node_to_buf.insert(*node_id, BufRef { backend, id: buf_id });
        }
        // 4. persistent 区（KV cache）首次分配后不再释放
    }

    pub fn fill_input(&mut self, graph: &ComputeGraph, name: &str, data: &[u8]) {
        // 输入数据填充：CPU 池直接写；GPU 池经 copy_to_gpu（同现状）
    }

    /// 仅 CPU 节点的 host 访问（GPU 节点经 backend copy 或直接设备内执行）
    pub fn get_buffer(&self, graph: &ComputeGraph, node: NodeId) -> Option<&[f32]>;
    pub fn alloc_persistent(&mut self, name: &str, backend: Backend, size: usize) -> BufRef;
}
```

所有权约定：**`GraphAllocator` 随图一起缓存在 `GraphCache` 中跨步骤存活**（修正项：原方案 §11 每步 `new()` + `reuse_alloc` 会丢掉缓冲本体）；复用步骤直接取出，不重建。KV persistent 区只分配一次。

```rust
pub struct BackendScheduler {

    pub node_range: (usize, usize), // range in graph.nodes

impl BackendScheduler {
```

### 3.5 Backend Trait (`src/graph/backend.rs`)

设备化接口（修正项：操作的是**本后端池内的缓冲 id**，不是 host slice）：

```rust
pub trait Backend: Send + Sync {
    fn name(&self) -> &str;

    /// 常规 op 支持能力（按 op + dtype）
    fn supports_op(&self, op: &Op, dtype: DType) -> bool;

    /// 融合 op 支持能力（驱动 fusion pass，避免双重融合）
    fn supports_fused(&self, fused: &FusedOp) -> bool;

    /// 本后端缓冲池：分配/释放（CPU = Vec<f32> 段；Metal = MTLBuffer 段；CUDA = device 段）
    fn alloc_buffer(&mut self, size: usize) -> usize;
    fn free_buffer(&mut self, id: usize);

    /// 执行单个节点：输入/输出均为本后端池内的缓冲 id。
    /// CPU backend 的池就是 Vec<f32>，可安全映射为 slice；
    /// Metal/CUDA backend 在池内取设备缓冲，权重按 node.meta 的 weight_name 查注册表。
    /// 跨后端传输不属于本接口——由 scheduler 在 split 边界负责。
    fn execute_node(&self, node: &CNode, in_bufs: &[usize], out_buf: usize);

    /// 后端内拷贝（视图/重排/部分行等场景）
    fn copy_buffer(&self, src: usize, dst: usize);

    fn synchronize(&self); // wait for async operations to complete
}
```

## 4. Qwen2 Graph Construction Example

```rust
// src/models/qwen2/graph.rs

impl Qwen2Model {
    pub fn build_graph(&self, params: &GraphParams) -> ComputeGraph {
        let mut b = GraphBuilder::new(BuilderContext {
            hparams: self.hparams.clone(),
            cparams: params.cparams.clone(),
            backend_caps: BackendCapabilities::current(),
        });

        // inputs（n_past 只影响这些输入的值，不影响拓扑）
        let inp_ids = b.input("token_ids", [params.n_tokens, 0, 0, 0], DType::I32);
        let inp_pos = b.input("positions", [params.n_tokens, 0, 0, 0], DType::I32);

        // Embedding
        let mut h = b.embedding(inp_ids, self.tok_embd.as_ref().unwrap());

        // per-layer
        for (il, layer) in self.layers.iter().enumerate() {
            let residual = h;

            // Pre-norm
            let normed = b.rms_norm(h, layer.attn_norm.as_ref(),
                                     self.hparams.f_norm_rms_eps);

            // QKV projection
            let q = b.matmul(normed, layer.wq.as_ref().unwrap(), layer.bq.as_ref());
            let k = b.matmul(normed, layer.wk.as_ref().unwrap(), layer.bk.as_ref());
            let v = b.matmul(normed, layer.wv.as_ref().unwrap(), layer.bv.as_ref());

            // RoPE
            let q = b.rope(q, inp_pos, RoPEMeta {
                freq_base: self.hparams.rope_freq_base,
                freq_scale: self.hparams.rope_freq_scale,
            });
            let k = b.rope(k, inp_pos, RoPEMeta {
                freq_base: self.hparams.rope_freq_base,
                freq_scale: self.hparams.rope_freq_scale,
            });

            // KV Cache：持久缓冲 + 位置数据（无 n_past）
            b.kvcache_store(il, k, v, inp_pos);
            let kv = b.kvcache_load(il, params.n_tokens,
                                     self.hparams.n_kv_embd as usize,
                                     self.hparams.n_head_kv as usize);

            // Attention
            let attn_out = b.attn(q, kv, AttnMeta {
                n_head: self.hparams.n_head as usize,
                n_head_kv: self.hparams.n_head_kv as usize,
                hd: self.hparams.n_embd_head() as usize,
                hd_kv: self.hparams.n_kv_embd as usize / self.hparams.n_head_kv as usize,
            });

            // Output proj
            let attn_out = b.matmul(attn_out, layer.wo.as_ref().unwrap(), None);

            // Residual
            h = b.add(residual, attn_out);

            // FFN
            let residual = h;
            let normed = b.rms_norm(h, layer.ffn_norm.as_ref(),
                                     self.hparams.f_norm_rms_eps);

            // SwiGLU: fusion pass 将 silu(gate)*up 折叠为 SwiGLU（GPU 已有 fused kernel）
            let gate = b.matmul(normed, layer.ffn_gate.as_ref().unwrap(), None);
            let up = b.matmul(normed, layer.ffn_up.as_ref().unwrap(), None);
            let ffn_out = b.swiglu(gate, up);

            let ffn_out = b.matmul(ffn_out, layer.ffn_down.as_ref().unwrap(), None);
            h = b.add(residual, ffn_out);
        }

        // output（decode 时经 GetRows 取尾部 n_out 行，见 §5.5）
        let normed = b.rms_norm(h, self.output_norm.as_ref(),
                                 self.hparams.f_norm_rms_eps);
        let logits = b.matmul(normed, self.output.as_ref().unwrap(),
                               self.output_b.as_ref());
        b.output(logits);

        b.build()
    }
}
```

## 5. Operator Fusion Rules

Implemented in `scheduler.fuse()`, via graph pattern matching。**每个融合仅当目标后端 `supports_fused` 时才生效**，且不得与后端已有融合 kernel 重复（见各规则标注）。

### 5.1 SwiGLU Fusion

```
Pattern: Mul(Silu(X), Y)
Replace: SwiGLU(X, Y)
Benefit: saves 1 buffer writeback, saves 1 kernel dispatch
```

现状：GPU 已有 `kernel_swiglu_f32`（metal.rs:742），本规则是把现有融合显式化；**CPU 尚无 fused kernel**（现为 in-place silu+mul 两趟）——若 CPU `supports_fused(SwiGLU)` 返回 true，需新增一次遍历的 fused kernel。

### 5.2 Batch QKV Fusion

```
Pattern: [MatMul(x, Wq), MatMul(x, Wk), MatMul(x, Wv)] (share same input x)
Replace: BatchMatMul(x, [Wq, Wk, Wv])
Benefit: shared quantized activations (quantize x once), saves 2 quantize dispatches
```

现状：GPU 路径已实现（`quant_matmul_f32_batch`，metal.rs:1610，仅全 Q4_0 时共享量化）；**CPU 回退路径逐 matmul 重新量化**（kernel.rs:75-80）——本规则在 CPU 上每层真实省 2 次量化，这是本方案 CPU 侧的主要融合收益。注意 `BatchMatMul` 的权重数量可变，IR 需用 src 切片表达。

### 5.3 Bias + RoPE Fusion

```
Pattern: RoPE(Add(x, bias))
Replace: FusedBiasRope(x, bias)
Benefit: saves 1 intermediate buffer, saves 1 dispatch
```

现状：GPU 已走更激进的 `attn_bias_rope_store`（add_bias×3 + rope×2 + store_kv×2 合成 1 个 dispatch，metal.rs:1053）。本规则在 IR 层表达同一融合的"bias+rope"部分；`FusedBiasRope` 的 IR 节点应携带"是否合并 store_kv"的标记以精确映射到现有 kernel。

### 5.4 Add + Norm Fusion (optional)

```
Pattern: RmsNorm(Add(a, b))
Replace: FusedAddRmsNorm(a, b)
Benefit: saves 1 writeback, but requires new kernel
```

### 5.5 n_out 尾部行优化（原"n_rows 属性"方案的替代）

llama.cpp 的解法是显式 `ggml_get_rows(cur, inp_out_ids)` 行选择节点（`src/models/llama.cpp` 最后层），比通用 `n_rows` 属性更干净：

```
Pattern: 末层 ffn 输入 → GetRows(hidden, tail_ids)   // tail_ids = [nt-n_out .. nt)
Benefit: decode 时末层 FFN/output 只计算尾部 n_out 行（现状 forward.rs 的手工优化）
```

实现：decode 构图时在末层 `ffn_norm` 前插入 `GetRows(h, tail_ids)`（`tail_ids` 为输入节点，每步填充），后续节点形状自动收窄；`GetRows` 已是 IR 一等 op，CPU/GPU kernel 均已有（embedding 查表同族）。

## 6. Graph Reuse Mechanism

**参数确定性复用**（修正项：不建图、不比节点序列；图拓扑是参数的确定性函数——与 llama.cpp `allow_reuse()` 同一不变式）：

```rust
pub struct GraphCache {
    graph: Option<ComputeGraph>,
    alloc: Option<GraphAllocator>,   // 跨步骤存活（含 persistent KV 区）
    prev_params: Option<GraphParams>,
}

impl GraphCache {
    /// 只比较参数：等价 ⇒ 拓扑必然相同 ⇒ 跳过重建与分配
    pub fn try_reuse(&mut self, new_params: &GraphParams) -> bool {
        match (&self.prev_params, &self.graph, &self.alloc) {
            (Some(prev), Some(_), Some(_)) if Self::params_match(prev, new_params) => {
                self.prev_params = Some(new_params.clone());
                true
            }
            _ => false,
        }
    }

    fn params_match(a: &GraphParams, b: &GraphParams) -> bool {
        a.n_tokens == b.n_tokens &&
        a.n_seqs == b.n_seqs &&
        a.gtype == b.gtype &&
        a.cparams == b.cparams &&
        a.weights_version == b.weights_version
    }

    /// debug 构建的二次校验：参数相同但结构不一致说明构建不确定，立即 panic
    #[cfg(debug_assertions)]
    fn verify_structural(&self, graph: &ComputeGraph) {
        if let Some(prev) = &self.graph {
            assert!(Self::graphs_equal(prev, graph),
                "graph rebuild with identical params produced different topology");
        }
    }

    pub fn store(&mut self, graph: ComputeGraph, alloc: GraphAllocator, params: GraphParams);
    pub fn current(&mut self) -> (&ComputeGraph, &mut GraphAllocator);
}
```

复用条件（与 `params_match` 对应）：

- 输入/输出形状相同（`n_tokens`、`n_seqs`）——batch size、seq len
- 图类型相同（`gtype`: decode/prefill）
- 运行时参数相同（`cparams`: flash_attn 等）
- 权重未变（`weights_version`：LoRA 切换、权重重载时由 model 递增）
- **`n_past` 不参与判定**——它是输入数据（positions 的值），不是图结构

## 7. Metal Per-Op Mapping

**关键事实（修正项）**：MpsState 的 per-op GPU 方法**已经全部存在**——`op_xxx()` 不需要新写，只需一个 adapter 把 `Backend::execute_node` 接到现有方法：

| Graph Op | 现有 MpsState 方法 | Metal kernel |
|----------|-------------------|--------------|
| `Op::RmsNorm` | `rms_norm()` (metal.rs:656) | `rms_norm.metal` |
| `Op::MatMul` | `quant_matmul_f32_on_gpu()` (414) / `quant_matmul_q8()` (588) | `q4_0_f32_matmul` etc. |
| `Op::BatchMatMul` | `quant_matmul_f32_batch()` (1610) | 共享 Q8_0 量化 + 批量 matmul |
| `Op::RoPE` | `rope_f32()` (769) | `rope_f32` |
| `Op::Silu` | `silu_f32()` (734) | `silu_f32` |
| `Op::SwiGLU` | `swiglu_f32()` (742) | `kernel_swiglu_f32` |
| `Op::FusedBiasRope` | `attn_bias_rope_store()` (1053) | `kernel_attn_bias_rope_store` |
| `Op::Add` | `add_f32()` (690) / `add_bias_f32()` (711) | `add_f32` |
| `Op::Mul` | `mul_f32()` (724) | `mul_f32` |
| `Op::Attn` | `gqa_attn_f32()` (791) / `gqa_attn_flash()` (871) / `attn_flash_prefill()` (999) | `gqa_attn_*` |
| `Op::GetRows` | `embed_tokens_gpu()` (631) | `get_rows` |
| `Op::KvcacheStore` | `store_kv()` (916) | `kv_store`（含 f16 路径） |
| `Op::KvcacheLoad` | KV 区视图（persistent MTLBuffer） | —（无拷贝） |

**Key change**：`layer_gpu()`（metal.rs:1853）目前把整层封装成一次不透明调用。重写后调度器可在层内决策（例如 QKV matmul 上 GPU、attention 下 CPU）——但受 §2 策略约束：**attention 与 KV cache 必须同后端**，避免每步 O(nkv) 的跨后端 KV 回传。

**Implementation strategy**：`layer_gpu()` 保留为"整层 GPU 快路径"（在整层所有 op 都上 GPU 时仍可走，避免逐节点调度开销）；`MetalBackend` 提供 per-op 执行路径。每个 GPU split 内的 op 共享一条 command buffer，仅在 split 边界 `submit()`（现状 forward.rs 的全模型单 cb 即此语义）。

### MetalBackend Implementation

```rust
// src/graph/metal_backend.rs

pub struct MetalBackend {
    state: MpsState,
}

impl Backend for MetalBackend {
    fn name(&self) -> &str { "metal" }

    fn supports_op(&self, op: &Op, dtype: DType) -> bool {
        match op {
            Op::RmsNorm => dtype == DType::F32,
            Op::MatMul { .. } => matches!(dtype, DType::F32 | DType::Q8_0),
            Op::RoPE => dtype == DType::F32,
            Op::Silu | Op::SwiGLU => dtype == DType::F32,
            Op::Add | Op::Mul => dtype == DType::F32,
            Op::Attn { .. } => dtype == DType::F32,
            Op::GetRows => dtype == DType::F32,
            Op::KvcacheStore | Op::KvcacheLoad => dtype == DType::F32,
            _ => false,
        }
    }

    fn supports_fused(&self, fused: &FusedOp) -> bool {
        // GPU 已有 swiglu / bias+rope+store kernel → 允许对应融合
        matches!(fused, FusedOp::SwiGLU | FusedOp::BiasRope)
    }

    fn execute_node(&self, node: &CNode, in_bufs: &[usize], out_buf: usize) {
        // in_bufs/out_buf 为本后端 MTLBuffer 池内的 id；
        // 权重按 node.meta 的 weight_name 查 weights 注册表（同 layer_gpu 现状）。
        // 例：
        //   Op::RmsNorm      → self.state.op_rms_norm(buf(in_bufs[0]), buf(out_buf), meta.eps)
        //   Op::MatMul{..}   → self.state.op_matmul(&meta.weight_name, buf(in_bufs[0]), buf(out_buf))
        //   Op::Attn{..}     → self.state.gqa_attn_f32 / gqa_attn_flash
        //   ...
    }

    fn synchronize(&self) {
        self.state.synchronize();
    }
}
```

```rust
fn forward(&self, tokens: &[u32], positions: &[usize], kv: &mut KVCache, n_out: usize) -> Vec<f32> {
    let params = GraphParams {
        n_tokens: tokens.len(),
        n_seqs: 1,
        gtype: if tokens.len() == 1 { GraphType::Decode } else { GraphType::Prefill },
        cparams: CParams::default(),
        weights_version: self.weights_version(),
    };
    let mut graph = self.build_graph(&params);
    let mut alloc = GraphAllocator::new();
    SCHEDULER.lock().unwrap().assign_backends(&mut graph);
    SCHEDULER.lock().unwrap().fuse(&mut graph);
    alloc.alloc_graph(&graph);
    SCHEDULER.lock().unwrap().execute(&graph, &mut alloc, tokens, positions, kv);
    alloc.get_buffer(&graph, graph.outputs[0]).unwrap().to_vec()
}
```

## 11. Main Inference Loop Refactor

```rust
// current:
let logits = model.forward(&input_ids, &positions, &mut kv_cache, 1);

// refactored:
let params = GraphParams {
    n_tokens: input_ids.len(),
    n_seqs: 1,
    gtype: if input_ids.len() == 1 { GraphType::Decode } else { GraphType::Prefill },
    cparams: CParams { flash_attn: true, .. },
    weights_version: model.weights_version(),
};

// 参数等价 → 复用（不建图、不分配）；否则重建并缓存
if !graph_cache.try_reuse(&params) {
    let mut graph = model.build_graph(&params);
    scheduler.assign_backends(&mut graph);
    scheduler.fuse(&mut graph);
    let mut alloc = GraphAllocator::new();
    alloc.alloc_graph(&graph);   // 含 KV persistent 区（首次）
    graph_cache.store(graph, alloc, params);
}

let (graph, mut alloc) = graph_cache.current();

// 填充输入数据（n_past 只影响这里的值，不影响拓扑）
alloc.fill_input(graph, "token_ids", &input_ids);
alloc.fill_input(graph, "positions", &positions);

scheduler.execute(graph, &mut alloc);
let logits = alloc.get_buffer(graph, graph.outputs[0]).unwrap().to_vec();
```

`execute()` 内部负责：KV store 的位置由 `positions` 输入驱动（等价于现 `store_multi(positions, …)`）、末层 `GetRows(tail_ids)` 的 `tail_ids` 填充、split 边界拷贝与 `submit()`。

## 12. Performance Expectations

> 修正项：GPU 融合 kernel 已存在，本方案的 GPU kernel 层收益有限；主要收益是（a）decode 跳过拓扑重建与 CPU scratch 分配，（b）CPU prefill 批量 QKV 共享量化，（c）层内 liveness 缓冲共享（层间/GPU 池已复用，故内存收益小于原估）。

| Scenario | Current | After Rewrite | Reason |
|----------|---------|---------------|--------|
| Decode nt=1 CPU | ~100 tok/s (0.5B) | ~100-105 tok/s | 跳过拓扑重建 + CPU scratch 复用（收益小但真实） |
| Decode nt=1 GPU | ~360 tok/s (0.5B) | ~360-370 tok/s | 融合 kernel 已存在；省的是主机侧构图/调度开销，kernel 层预期持平 |
| Prefill nt=128 GPU | ~800 tok/s | ~820-860 tok/s | CPU 侧批量 QKV 共享量化（GPU 已共享 Q4_0）；融合显式化为后续优化铺路 |

| Peak memory | Fixed (full buffers per layer) | 10-20% reduction | 层内 liveness 复用（层间与 GPU 池本已复用，故低于原估 20-30%） |

## 15. Key Risks and Countermeasures

| Risk | Impact | Countermeasure |
|------|--------|----------------|
| **KV cache 位置耦合（原方案致命缺陷，已修正）** | n_past 进 IR 会让 decode 每步拓扑变化、图复用失效 | KV 为 persistent 外部缓冲；`KvcacheStore/Load` 只带 layer；位置经 `positions` 输入注入（与 llama.cpp 一致） |
| **复用判定过松/漏比负载** | cparams/LoRA 变化时静默复用错误语义的图 | 参数确定性判定（gtype/cparams/n_tokens/n_seqs/weights_version）；`Op: PartialEq` 全负载比较做 debug 二次校验 |
| **Backend 接口 host 往返** | 每节点 CPU↔GPU 拷贝会慢一个数量级 | Backend trait 操作后端池内缓冲 id；跨后端传输只在 split 边界发生 |
| **n_out 优化丢失** | decode 末层多算 n_out 之外的行 | 改用 `GetRows(hidden, tail_ids)` 行选择节点（llama.cpp `inp_out_ids` 同款） |
| **Metal per-op dispatch overhead** | 逐 op 独立提交可能慢于整层提交 | 同 split 内 op 共享一条 command buffer，仅 split 边界 submit；整层全 GPU 时仍可走 `layer_gpu()` 快路径 |
| **跨后端 KV 拷贝** | QKV 上 GPU、attention 下 CPU 时每步 O(nkv) 回传 | 调度策略：attention 与 KV cache 强制同后端 |
| **双重融合** | fusion pass 与现有 fused kernel 重复 | 融合由 `supports_fused` 驱动，GPU 侧 SwiGLU/BiasRope 融合节点直连现有 kernel |
| **Performance regression** | 构图 + 调度有固定开销 | 参数确定性复用：decode 拓扑不变，跳过重建与分配 |
| **GPU 安全规则破坏** | guard 失败被误当支持性回退 | 保留 GPU_SAFETY.md 语义：设备限制类 guard → `gpu_abort`；仅 Raw 权重等支持性限制 → 回退（构图期即确定） |
| **CUDA 功能回归** | 现有 CUDA Graph 捕获/回放丢失 | CudaBackend 包装 cuda.rs 并保留 CUDA Graph（uid 键） |
| **DOT export increases code** | ~80 lines additional code | Feature-gated (`#[cfg(feature = "graph_dump")]`) |

### 实施中偏离计划文档的记录

1. **`NodeMeta` 用具体 enum 代替 `Box<dyn Any + Send + Sync>`**（`src/graph/ops.rs`）：可 `PartialEq`（供 debug 复用校验）、无 downcast panic、`CNode` 可 `Clone`。代价：新增元数据类型需改 enum（已含 MatMul/Norm/Rope/Attn/Kvcache/Embed）。
2. **`Op::Input` 叶子节点**：输入节点用独立 op 标记（对应 llama.cpp `GGML_OP_NONE` 叶），`ComputeGraph::inputs` 记录其 id。
3. **`rope()` 增加 `style: RopeStyle` 参数**（计划示例签名未含，但 minfer `ModelDef::rope_style()` 需要它）；**`kvcache_store/load` 显式携带 `n_ctx`** 用于持久区定长（load 形状 `[n_embd, n_ctx]`，执行期只读已写前缀）。
4. **KV 持久区布局 `[K | V]` 连续**（每层一块，长度 `2*n_embd*n_ctx`；Phase 2 起由 allocator 保证，attention kernel 从一个 buffer 取 K 与 V）。
5. **`attn()` 增加 `pos` 输入**（计划签名 `attn(q, kv_layer, meta)` 无位置——但因果 mask 需要 `pos[t]+1`；llama.cpp 的 mask 同样依赖 idx 输入）。
6. **meta 结构扩展**：`EmbedMeta.weight_name`、`RoPEMeta.n_head/hd`、`AttnMeta.nkt/scale`（kernel 必需，计划 §3.1 未列）。
7. **`Backend::execute_node` 用 `&mut self`**（CPU 池需可变访问；GPU 后端命令缓冲同理）；**缓冲池单一持有者 = `GraphAllocator`**（scheduler 经 allocator 执行，避免双池）。
8. **I32 输入（token ids/positions）以 `f32::from_bits` 位模式存储**（|v| < 2^24 精确），allocator 提供 `fill_input_i32`。
9. **F32 权重 matmul 在 CPU backend 支持**（现有 `cpu_quant_matmul_f32` 对 F32 panic，graph 路径经 `vec_ops::mat_mul_f32` 兜底）。
10. **BatchMatMul 融合推迟**：单输出 IR（`CNode` 一个 out buffer）无法表达多输出融合节点；待 Phase 5 评估 IR 扩展（concat+view 或 多输出节点）。SwiGLU/BiasRope 融合已实现并按 backend `supports_fused` 门控。
11. **缓冲池单一持有者 = `GraphAllocator`**（Phase 2 偏差的最终形态）：scheduler 是纯编排器（`assign_backends(graph, alloc)` 经 allocator 能力查询），执行经 `alloc.cpu_mut()`。Phase 3 加 Metal 池时在 allocator 内并列持有。
12. **`GraphParams`（`graph/params.rs`）即复用判定的全部依据**：n_tokens/n_seqs/gtype/cparams/weights_version；`n_past` 明确缺席（执行期数据）。`weights_version` 用全局原子计数器，Phase 6 由模型接线。
