# minfer Compute Graph Architecture Rewrite Plan

Rewrite minfer from imperative forward pass to declarative compute graph architecture, targeting llama.cpp's `ggml_cgraph` + backend scheduler design.

> Revision note (2026-08): corrections based on line-by-line verification against llama.cpp HEAD `749f688fc`:
> 1. **KV cache positions are data**——`n_past` no longer enters the graph IR (the original plan encoded `n_past` into `KvcacheLoad`, which causes the decode topology to change at every step and structurally breaks graph reuse); the KV cache becomes a persistent external buffer, with positions injected through input nodes (llama.cpp's `allow_reuse` does not compare `n_past`).
> 2. **Reuse decision changed to parameter determinism**——no longer "build graph then compare" (the original `try_reuse(new_graph)` cannot skip the rebuild), and no longer uses `mem::discriminant` to compare only the variant (which would miss comparing payloads like `transpose_b`/`eps`/`weight_name`); following `llm_graph_params::allow_reuse`, only parameters are compared.
> 3. **Backend abstraction made device-oriented**——the original `execute_node(&[&[f32]] -> &mut [f32])` is a pure CPU slice interface; landing Metal requires either a host round trip per node or a distorted trait; changed to a backend-owned buffer pool + buffer id.
> 4. **Correct the current-state description**——minfer already has substantial manual fusion (GPU `swiglu_f32`/`attn_bias_rope_store`/fused qkv+gu kernel, batched matmul shared quantization); this plan is about "making fusion explicit", not "building from scratch"; CUDA wraps the existing `cuda.rs` (including CUDA Graph), **not a stub**.

---

## 1. Design Goals

| Goal | Current State | Target State |
|------|---------------|--------------|
| Multi-backend dispatch | forward.rs hardcodes GPU/CPU paths | Backend assigned per op at graph build time, auto partition |
| Operator fusion | **Manual fusion already exists**: GPU `swiglu_f32`, `attn_bias_rope_store` (add_bias×3+rope×2+store_kv×2 → 1 dispatch), `blk.attn_qkv`/`ffn_gu` fused weights, batched matmul shared quantization (Q4_0); CPU batched matmul but **requantizes per matmul** | Fusion becomes a first-class IR citizen (`SwiGLU`/`FusedBiasRope`/`BatchMatMul`), generated by pattern matching and dispatched by backend capability (`supports_fused`), composable and portable |
| Graph reuse | Recomputes topology every step + CPU scratch reallocation (GPU buffers already reused across calls via the `get_or_grow` pool) | Parameter-deterministic reuse: same-topology graph skips rebuild and allocation, only updates input data |
| Extensibility | New models require rewriting entire forward.rs (~620 lines) | New models only need graph construction (~200 lines), reuse all infrastructure |
| GPU fallback | Runtime `layer_gpu()` returns false to fallback to CPU | Backend decided at graph build time based on weight registration status (**preserve the GPU_SAFETY.md distinction: guard failure → `gpu_abort`; only support limitation → fallback**) |
| CUDA | Already has `cuda.rs` (`layer_gpu` + CUDA Graph capture/replay, feature-gated) | Wrap as `CudaBackend`, preserving CUDA Graph (keyed by graph `uid`)——**not a stub** |

## 2. Overall Architecture

```
                  ┌──────────────────────────────────┐
                  │       GraphBuilder (per arch)      │
                  │  Builds ComputeGraph (declarative IR)│
                  └──────────┬───────────────────────┘
                             │ ComputeGraph
                             ▼
                  ┌──────────────────────────────────┐
                  │       BackendScheduler             │
                  │  1. assign_backend(): per op → GPU/CPU │
                  │  2. fuse(): fusion pass (capability-driven) │
                  │  3. split_graph(): partition into subgraphs │
                  │  4. allocate(): per-backend buffer alloc+reuse │
                  └──────────┬───────────────────────┘
                             │
                ┌────────────┼────────────┐
                ▼            ▼            ▼
          ┌──────────┐ ┌──────────┐ ┌──────────┐
          │ CpuBackend│ │MetalBack │ │CudaBackend│
          │(kernel.rs)│ │(mps op)  │ │(cuda.rs) │
          └──────────┘ └──────────┘ └──────────┘
```

Scheduler policy (new, from verification of llama.cpp behavior):

- **attention and KV cache are forced to the same backend**——avoiding cross-backend KV copies (the per-step O(nkv) GPU↔CPU round trip is the "KV-growth decode cost" that minfer currently deliberately avoids).
- **GPU ops within the same split share a single command buffer**, submitted only at split boundaries (the current forward.rs already uses a single cb for the whole model; this needs to be preserved and formalized in the scheduler).
- **Fusion is driven by the backend `supports_fused`**——fusion is not forced, to avoid double-fusion with existing fused kernels.

## 3. Core Data Structures

### 3.1 Compute Graph IR (`src/graph/mod.rs`)

```rust
pub type NodeId = usize;

#[derive(Clone, Copy, PartialEq, Eq, Debug)]
pub enum DType { F32, F16, I32, Q8_0 }

/// Operator type
#[derive(Clone, PartialEq, Debug)] // PartialEq: fully compares payloads (including transpose_b/eps, etc.),
                                    // used by the debug-build reuse consistency check; the actual reuse decision goes through parameter comparison
pub enum Op {
    // Element-wise
    Add,
    Mul,
    Scale(f32),
    Silu,

    // Reduction
    Softmax { dim: usize },

    // Normalization
    RmsNorm { eps: f32 },

    // Linear algebra
    MatMul { transpose_b: bool },

    // Indexing
    GetRows,  // embedding lookup / row selection (also used for n_out tail rows, see §5.5)

    // Positional encoding
    RoPE { style: RopeStyle },

    // Attention
    Attn { mode: AttnMode },

    // KV Cache —— persistent external buffer + position data injection; n_past does not enter the IR
    KvcacheStore { layer: usize },  // writes this step's k/v into the persistent KV region (write position comes from the positions input)
    KvcacheLoad { layer: usize },   // reads historical KV (a view of the persistent KV region), topology independent of n_past

    // View/reshape
    View { offset: usize, shape: [usize; 4] },
    Reshape { shape: [usize; 4] },
    Permute { dims: [usize; 4] },

    // Fused ops (generated by fusion pass, gated by backend supports_fused)
    SwiGLU,            // silu(gate) * up —— GPU already has kernel_swiglu_f32; CPU needs a new kernel or runtime decomposition
    FusedBiasRope,     // add_bias + rope —— GPU already has attn_bias_rope_store (which also merges store_kv)
    BatchMatMul,       // multiple matmuls sharing input —— GPU already has it (Q4_0 shared quantization); CPU needs shared quantization
}

#[derive(Clone, Copy, PartialEq, Eq, Debug)]
pub enum AttnMode { Mha, Gqa, Flash }

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Backend { CPU, Metal, Cuda }

/// Single compute node
pub struct CNode {
    pub id: NodeId,
    pub name: String,
    pub op: Op,
    pub src: Vec<NodeId>,        // input dependencies
    pub out_shape: [usize; 4],   // output shape
    pub out_dtype: DType,        // output data type
    pub backend: Option<Backend>, // None = decided by scheduler
    pub meta: Box<dyn Any + Send + Sync>, // op-specific metadata
}

/// Op metadata types
pub struct MatMulMeta { pub weight_name: String, pub bias_name: Option<String> }
pub struct RoPEMeta { pub freq_base: f32, pub freq_scale: f32 }
pub struct AttnMeta { pub n_head: usize, pub n_head_kv: usize, pub hd: usize, pub hd_kv: usize }
pub struct KvcacheMeta { pub n_embd: usize, pub n_head_kv: usize }
pub struct EmbedMeta { pub vocab_size: usize }

/// Compute graph
pub struct ComputeGraph {
    pub nodes: Vec<CNode>,
    pub inputs: Vec<NodeId>,     // input nodes that need external filling
    pub outputs: Vec<NodeId>,    // output nodes (logits, etc.)
    pub uid: u64,                // graph identifier, used for reuse detection such as CUDA Graph caching
    pub persistent: Vec<PersistentBuf>, // descriptions of persistent buffers such as KV cache (actual storage owned by the allocator)
}
```

**Key KV cache convention (correction)**: `KvcacheStore`/`KvcacheLoad` carry no position information. The KV data region is allocated by the allocator via `alloc_persistent` (one block per layer, shape = `[n_embd, n_ctx]`, a resident segment within the MTLBuffer pool on the GPU path), and graph nodes only declare "read/write of layer `layer`". Each step's write position = the value of the `positions` input node (consistent with the current forward.rs `store_multi(positions, …)` semantics). Therefore **the graph topology does not change with KV length**——this is the precondition for decode graph reuse, consistent with llama.cpp `allow_reuse()` not comparing `n_past`.

### 3.3 Memory Allocator (`src/graph/alloc.rs`)

Pooled per backend (correction: no longer just `Vec<f32>`; Metal/CUDA pools each hold device buffers, equivalent to llama.cpp `ggml_gallocr`'s per-backend buffer pools):

```rust
/// Buffer handle: backend + id within that backend's pool
#[derive(Clone, Copy, PartialEq, Eq, Debug)]
pub struct BufRef { pub backend: Backend, pub id: usize }

pub struct GraphAllocator {
    cpu: CpuBufferPool,                       // Vec<f32> segmented pool (liveness reuse)
    #[cfg(target_os = "macos")]
    metal: MetalBufferPool,                   // MTLBuffer segmented pool (ported from get_or_grow)
    #[cfg(feature = "cuda")]
    cuda: CudaBufferPool,                     // ports cuda.rs buffer management
    node_to_buf: HashMap<NodeId, BufRef>,
    persistent: Vec<PersistentBuf>,           // resident regions such as KV cache (survive across steps)
}

pub struct PersistentBuf { pub name: String, pub backend: Backend, pub id: usize }

impl GraphAllocator {
    /// liveness analysis + per-backend buffer allocation
    pub fn alloc_graph(&mut self, graph: &ComputeGraph) {
        // 1. topological sort
        let order = graph.topo_order();
        // 2. compute liveness interval [start, end) for each node
        let liveness = self.compute_liveness(&order, graph);
        // 3. greedy allocation: nodes with non-overlapping liveness share segments
        //    allocation goes to the corresponding backend pool based on node backend (after assign)
        for node_id in &order {
            let buf_size = graph.nodes[*node_id].out_shape.iter().product::<usize>();
            let backend = graph.nodes[*node_id].backend.unwrap();
            let buf_id = self.find_reusable_buffer(backend, buf_size, &liveness, *node_id);
            self.node_to_buf.insert(*node_id, BufRef { backend, id: buf_id });
        }
        // 4. the persistent region (KV cache) is never freed after its first allocation
    }

    pub fn fill_input(&mut self, graph: &ComputeGraph, name: &str, data: &[u8]) {
        // input data fill: CPU pool written directly; GPU pool via copy_to_gpu (same as current)
    }

    /// host access for CPU nodes only (GPU nodes via backend copy or direct in-device execution)
    pub fn get_buffer(&self, graph: &ComputeGraph, node: NodeId) -> Option<&[f32]>;
    pub fn alloc_persistent(&mut self, name: &str, backend: Backend, size: usize) -> BufRef;
}
```

Ownership convention: **`GraphAllocator` is cached together with the graph in `GraphCache` and survives across steps** (correction: the original plan §11's per-step `new()` + `reuse_alloc` would discard the buffer objects themselves); reuse steps simply retrieve it without rebuilding. The KV persistent region is allocated only once.

### 3.5 Backend Trait (`src/graph/backend.rs`)

Device-oriented interface (correction: it operates on **buffer ids within this backend's pool**, not host slices):

```rust
pub trait Backend: Send + Sync {
    fn name(&self) -> &str;

    /// regular op support capability (by op + dtype)
    fn supports_op(&self, op: &Op, dtype: DType) -> bool;

    /// fused op support capability (drives the fusion pass, avoiding double fusion)
    fn supports_fused(&self, fused: &FusedOp) -> bool;

    /// this backend's buffer pool: allocate/free (CPU = Vec<f32> segments; Metal = MTLBuffer segments; CUDA = device segments)
    fn alloc_buffer(&mut self, size: usize) -> usize;
    fn free_buffer(&mut self, id: usize);

    /// execute a single node: inputs/outputs are buffer ids within this backend's pool.
    /// the CPU backend's pool is a Vec<f32>, safely mappable to a slice;
    /// Metal/CUDA backends take device buffers from the pool; weights are looked up in the registry by node.meta weight_name.
    /// cross-backend transfers are not part of this interface——handled by the scheduler at split boundaries.
    fn execute_node(&self, node: &CNode, in_bufs: &[usize], out_buf: usize);

    /// in-backend copy (for views/reshapes/partial rows, etc.)
    fn copy_buffer(&self, src: usize, dst: usize);

    fn synchronize(&self); // wait for async operations to complete
}
```

## 4. Qwen2 Graph Construction Example

```rust
// src/models/qwen2/graph.rs

impl Qwen2Model {
    pub fn build_graph(&self, params: &GraphParams) -> ComputeGraph {
        let mut b = GraphBuilder::new(BuilderContext {
            hparams: self.hparams.clone(),
            cparams: params.cparams.clone(),
            backend_caps: BackendCapabilities::current(),
        });

        // inputs (n_past only affects the values of these inputs, not the topology)
        let inp_ids = b.input("token_ids", [params.n_tokens, 0, 0, 0], DType::I32);
        let inp_pos = b.input("positions", [params.n_tokens, 0, 0, 0], DType::I32);

        // Embedding
        let mut h = b.embedding(inp_ids, self.tok_embd.as_ref().unwrap());

        // per-layer
        for (il, layer) in self.layers.iter().enumerate() {
            let residual = h;

            // Pre-norm
            let normed = b.rms_norm(h, layer.attn_norm.as_ref(),
                                     self.hparams.f_norm_rms_eps);

            // QKV projection
            let q = b.matmul(normed, layer.wq.as_ref().unwrap(), layer.bq.as_ref());
            let k = b.matmul(normed, layer.wk.as_ref().unwrap(), layer.bk.as_ref());
            let v = b.matmul(normed, layer.wv.as_ref().unwrap(), layer.bv.as_ref());

            // RoPE
            let q = b.rope(q, inp_pos, RoPEMeta {
                freq_base: self.hparams.rope_freq_base,
                freq_scale: self.hparams.rope_freq_scale,
            });
            let k = b.rope(k, inp_pos, RoPEMeta {
                freq_base: self.hparams.rope_freq_base,
                freq_scale: self.hparams.rope_freq_scale,
            });

            // KV Cache: persistent buffer + position data (no n_past)
            b.kvcache_store(il, k, v, inp_pos);
            let kv = b.kvcache_load(il, params.n_tokens,
                                     self.hparams.n_kv_embd as usize,
                                     self.hparams.n_head_kv as usize);

            // Attention
            let attn_out = b.attn(q, kv, AttnMeta {
                n_head: self.hparams.n_head as usize,
                n_head_kv: self.hparams.n_head_kv as usize,
                hd: self.hparams.n_embd_head() as usize,
                hd_kv: self.hparams.n_kv_embd as usize / self.hparams.n_head_kv as usize,
            });

            // Output proj
            let attn_out = b.matmul(attn_out, layer.wo.as_ref().unwrap(), None);

            // Residual
            h = b.add(residual, attn_out);

            // FFN
            let residual = h;
            let normed = b.rms_norm(h, layer.ffn_norm.as_ref(),
                                     self.hparams.f_norm_rms_eps);

            // SwiGLU: the fusion pass folds silu(gate)*up into SwiGLU (GPU already has a fused kernel)
            let gate = b.matmul(normed, layer.ffn_gate.as_ref().unwrap(), None);
            let up = b.matmul(normed, layer.ffn_up.as_ref().unwrap(), None);
            let ffn_out = b.swiglu(gate, up);

            let ffn_out = b.matmul(ffn_out, layer.ffn_down.as_ref().unwrap(), None);
            h = b.add(residual, ffn_out);
        }

        // output (during decode, GetRows takes the tail n_out rows; see §5.5)
        let normed = b.rms_norm(h, self.output_norm.as_ref(),
                                 self.hparams.f_norm_rms_eps);
        let logits = b.matmul(normed, self.output.as_ref().unwrap(),
                               self.output_b.as_ref());
        b.output(logits);

        b.build()
    }
}
```

## 5. Operator Fusion Rules

Implemented in `scheduler.fuse()`, via graph pattern matching. **Each fusion only takes effect when the target backend `supports_fused`**, and must not duplicate an existing backend fused kernel (see notes on each rule).

### 5.1 SwiGLU Fusion

```
Pattern: Mul(Silu(X), Y)
Replace: SwiGLU(X, Y)
Benefit: saves 1 buffer writeback, saves 1 kernel dispatch
```

Current state: GPU already has `kernel_swiglu_f32` (metal.rs:742); this rule makes the existing fusion explicit; **CPU has no fused kernel yet** (currently an in-place silu+mul in two passes)——if CPU `supports_fused(SwiGLU)` returns true, a single-pass fused kernel must be added.

### 5.2 Batch QKV Fusion

```
Pattern: [MatMul(x, Wq), MatMul(x, Wk), MatMul(x, Wv)] (share same input x)
Replace: BatchMatMul(x, [Wq, Wk, Wv])
Benefit: shared quantized activations (quantize x once), saves 2 quantize dispatches
```

Current state: GPU path already implemented (`quant_matmul_f32_batch`, metal.rs:1610, shared quantization only for all-Q4_0); **the CPU fallback path requantizes per matmul** (kernel.rs:75-80)——this rule genuinely saves 2 quantizations per layer on CPU, which is the main fusion benefit of this plan on the CPU side. Note `BatchMatMul` has a variable number of weights; the IR must express it via src slices.

### 5.3 Bias + RoPE Fusion

```
Pattern: RoPE(Add(x, bias))
Replace: FusedBiasRope(x, bias)
Benefit: saves 1 intermediate buffer, saves 1 dispatch
```

Current state: GPU already uses the more aggressive `attn_bias_rope_store` (add_bias×3 + rope×2 + store_kv×2 combined into 1 dispatch, metal.rs:1053). This rule expresses the "bias+rope" part of the same fusion at the IR level; the `FusedBiasRope` IR node should carry a "whether to merge store_kv" flag to map precisely onto the existing kernel.

### 5.4 Add + Norm Fusion (optional)

```
Pattern: RmsNorm(Add(a, b))
Replace: FusedAddRmsNorm(a, b)
Benefit: saves 1 writeback, but requires new kernel
```

### 5.5 n_out Tail Row Optimization (replacement for the original "n_rows attribute" approach)

llama.cpp's solution is an explicit `ggml_get_rows(cur, inp_out_ids)` row-selection node (`src/models/llama.cpp` final layer), which is cleaner than a generic `n_rows` attribute:

```
Pattern: final layer ffn input → GetRows(hidden, tail_ids)   // tail_ids = [nt-n_out .. nt)
Benefit: during decode the final-layer FFN/output only computes the tail n_out rows (the manual optimization in the current forward.rs)
```

Implementation: when building the decode graph, insert `GetRows(h, tail_ids)` before the final `ffn_norm` (`tail_ids` is an input node filled each step), and subsequent node shapes automatically narrow; `GetRows` is already a first-class IR op with both CPU/GPU kernels (same family as embedding lookup).

## 6. Graph Reuse Mechanism

**Parameter-deterministic reuse** (correction: no graph build, no node-sequence comparison; the graph topology is a deterministic function of the parameters——the same invariant as llama.cpp `allow_reuse()`):

```rust
pub struct GraphCache {
    graph: Option<ComputeGraph>,
    alloc: Option<GraphAllocator>,   // survives across steps (including the persistent KV region)
    prev_params: Option<GraphParams>,
}

impl GraphCache {
    /// compares only parameters: equivalent ⇒ topology necessarily identical ⇒ skip rebuild and allocation
    pub fn try_reuse(&mut self, new_params: &GraphParams) -> bool {
        match (&self.prev_params, &self.graph, &self.alloc) {
            (Some(prev), Some(_), Some(_)) if Self::params_match(prev, new_params) => {
                self.prev_params = Some(new_params.clone());
                true
            }
            _ => false,
        }
    }

    fn params_match(a: &GraphParams, b: &GraphParams) -> bool {
        a.n_tokens == b.n_tokens &&
        a.n_seqs == b.n_seqs &&
        a.gtype == b.gtype &&
        a.cparams == b.cparams &&
        a.weights_version == b.weights_version
    }

    /// secondary check in debug builds: identical params but inconsistent structure means the build is non-deterministic; panic immediately
    #[cfg(debug_assertions)]
    fn verify_structural(&self, graph: &ComputeGraph) {
        if let Some(prev) = &self.graph {
            assert!(Self::graphs_equal(prev, graph),
                "graph rebuild with identical params produced different topology");
        }
    }

    pub fn store(&mut self, graph: ComputeGraph, alloc: GraphAllocator, params: GraphParams);
    pub fn current(&mut self) -> (&ComputeGraph, &mut GraphAllocator);
}
```

Reuse conditions (corresponding to `params_match`):

- Same input/output shapes (`n_tokens`, `n_seqs`)——batch size, seq len
- Same graph type (`gtype`: decode/prefill)
- Same runtime parameters (`cparams`: flash_attn, etc.)
- Weights unchanged (`weights_version`: incremented by the model on LoRA switch or weight reload)
- **`n_past` does not participate in the decision**——it is input data (the value of positions), not graph structure

## 7. Metal Per-Op Mapping

**Key fact (correction)**: MpsState's per-op GPU methods **already all exist**——`op_xxx()` need not be newly written; only an adapter is needed to connect `Backend::execute_node` to the existing methods:

| Graph Op | Existing MpsState method | Metal kernel |
|----------|-------------------|--------------|
| `Op::RmsNorm` | `rms_norm()` (metal.rs:656) | `rms_norm.metal` |
| `Op::MatMul` | `quant_matmul_f32_on_gpu()` (414) / `quant_matmul_q8()` (588) | `q4_0_f32_matmul` etc. |
| `Op::BatchMatMul` | `quant_matmul_f32_batch()` (1610) | shared Q8_0 quantization + batched matmul |

**Key change**: `layer_gpu()` (metal.rs:1853) currently wraps the entire layer as one opaque call. After the rewrite the scheduler can decide within a layer (e.g. QKV matmul on GPU, attention on CPU)——but constrained by the §2 policy: **attention and KV cache must share the same backend**, to avoid the per-step O(nkv) cross-backend KV round trip.

**Implementation strategy**: `layer_gpu()` is kept as a "whole-layer GPU fast path" (still usable when all ops in a layer go to GPU, avoiding per-node scheduling overhead); `MetalBackend` provides the per-op execution path. Ops within a GPU split share one command buffer, `submit()` only at split boundaries (the current forward.rs whole-model single cb is exactly this semantics).

### MetalBackend Implementation

```rust
// src/graph/metal_backend.rs

pub struct MetalBackend {
    state: MpsState,
}

impl Backend for MetalBackend {
    fn name(&self) -> &str { "metal" }

    fn supports_op(&self, op: &Op, dtype: DType) -> bool {
        match op {
            Op::RmsNorm => dtype == DType::F32,
            Op::MatMul { .. } => matches!(dtype, DType::F32 | DType::Q8_0),
            Op::RoPE => dtype == DType::F32,
            Op::Silu | Op::SwiGLU => dtype == DType::F32,
            Op::Add | Op::Mul => dtype == DType::F32,
            Op::Attn { .. } => dtype == DType::F32,
            Op::GetRows => dtype == DType::F32,
            Op::KvcacheStore | Op::KvcacheLoad => dtype == DType::F32,
            _ => false,
        }
    }

    fn supports_fused(&self, fused: &FusedOp) -> bool {
        // GPU already has swiglu / bias+rope+store kernels → allow the corresponding fusion
        matches!(fused, FusedOp::SwiGLU | FusedOp::BiasRope)
    }

    fn execute_node(&self, node: &CNode, in_bufs: &[usize], out_buf: usize) {
        // in_bufs/out_buf are ids within this backend's MTLBuffer pool;
        // weights are looked up in the weights registry by node.meta weight_name (same as layer_gpu's current behavior).
        // e.g.:
        //   Op::RmsNorm      → self.state.op_rms_norm(buf(in_bufs[0]), buf(out_buf), meta.eps)
        //   Op::MatMul{..}   → self.state.op_matmul(&meta.weight_name, buf(in_bufs[0]), buf(out_buf))
        //   Op::Attn{..}     → self.state.gqa_attn_f32 / gqa_attn_flash
        //   ...
    }

    fn synchronize(&self) {
        self.state.synchronize();
    }
}
```

```rust
impl ComputeGraph {
    /// Export Graphviz DOT format
    pub fn dump_dot(&self, w: &mut impl Write) -> io::Result<()> {
        writeln!(w, "digraph G {{")?;
        writeln!(w, "  rankdir=LR;")?;
        writeln!(w, "  node [shape=record fontname=\"monospace\"];")?;

        for node in &self.nodes {
            let color = match node.backend {
                Some(Backend::Metal) => "lightblue",
                Some(Backend::CPU) => "lightyellow",
                Some(Backend::Cuda) => "lightgreen",
                None => "white",
            };
            let label = format!("{}\\n{:?}", node.name, node.op);
            writeln!(w,
                "  n{} [label=\"{}\" style=filled fillcolor={}]",
                node.id, label, color
            )?;
        }

        for node in &self.nodes {
            for &src in &node.src {
                writeln!(w, "  n{} -> n{}", src, node.id)?;
            }
        }

        // mark inputs/outputs
        for &inp in &self.inputs {
            writeln!(w, "  n{} [label=\"INPUT\\n{}\" shape=doublecircle]",
                inp, self.nodes[inp].name)?;
        }
        for &out in &self.outputs {
            writeln!(w, "  n{} [label=\"OUTPUT\\n{}\" shape=doublecircle]",
                out, self.nodes[out].name)?;
        }

        writeln!(w, "}}")
    }
}
```

```rust
pub struct GraphParams {
    pub n_tokens: usize,     // batch size
    pub n_seqs: usize,       // number of sequences (minfer is currently 1, reserved)
    pub gtype: GraphType,    // Decode / Prefill / ...

```

**Note (correction)**: `GraphParams` has **no `n_past`**——KV positions are execution-time input data, injected via the `positions` input node. `forward()` is kept as a convenience entry (internal `build_graph` + single-step execution); the main inference loop uses the §11 cached path.

Default `forward()` implementation:
```rust
fn forward(&self, tokens: &[u32], positions: &[usize], kv: &mut KVCache, n_out: usize) -> Vec<f32> {
    let params = GraphParams {
        n_tokens: tokens.len(),
        n_seqs: 1,
        gtype: if tokens.len() == 1 { GraphType::Decode } else { GraphType::Prefill },
        cparams: CParams::default(),
        weights_version: self.weights_version(),
    };
    let mut graph = self.build_graph(&params);
    let mut alloc = GraphAllocator::new();
    SCHEDULER.lock().unwrap().assign_backends(&mut graph);
    SCHEDULER.lock().unwrap().fuse(&mut graph);
    alloc.alloc_graph(&graph);
    SCHEDULER.lock().unwrap().execute(&graph, &mut alloc, tokens, positions, kv);
    alloc.get_buffer(&graph, graph.outputs[0]).unwrap().to_vec()
}
```

## 11. Main Inference Loop Refactor

```rust
// current:
let logits = model.forward(&input_ids, &positions, &mut kv_cache, 1);

// refactored:
let params = GraphParams {
    n_tokens: input_ids.len(),
    n_seqs: 1,
    gtype: if input_ids.len() == 1 { GraphType::Decode } else { GraphType::Prefill },
    cparams: CParams { flash_attn: true, .. },
    weights_version: model.weights_version(),
};

// params equivalent → reuse (no build, no allocation); otherwise rebuild and cache
if !graph_cache.try_reuse(&params) {
    let mut graph = model.build_graph(&params);
    scheduler.assign_backends(&mut graph);
    scheduler.fuse(&mut graph);
    let mut alloc = GraphAllocator::new();
    alloc.alloc_graph(&graph);   // includes the KV persistent region (first time)
    graph_cache.store(graph, alloc, params);
}

let (graph, mut alloc) = graph_cache.current();

// fill input data (n_past only affects the values here, not the topology)
alloc.fill_input(graph, "token_ids", &input_ids);
alloc.fill_input(graph, "positions", &positions);

scheduler.execute(graph, &mut alloc);
let logits = alloc.get_buffer(graph, graph.outputs[0]).unwrap().to_vec();
```

`execute()` internally handles: the KV store position driven by the `positions` input (equivalent to the current `store_multi(positions, …)`), filling `tail_ids` for the final-layer `GetRows(tail_ids)`, split-boundary copies and `submit()`.

## 12. Performance Expectations

> Correction: GPU fused kernels already exist, so this plan's GPU kernel-layer gains are limited; the main gains are (a) decode skipping topology rebuild and CPU scratch allocation, (b) CPU prefill batched QKV shared quantization, (c) intra-layer liveness buffer sharing (inter-layer/GPU pools already reuse, so memory gains are smaller than originally estimated).

## 15. Key Risks and Countermeasures

| Risk | Impact | Countermeasure |
|------|--------|----------------|
| **KV cache position coupling (fatal flaw in the original plan, now fixed)** | n_past entering the IR causes the decode topology to change at every step and graph reuse to fail | KV is a persistent external buffer; `KvcacheStore/Load` carry only layer; positions injected via the `positions` input (consistent with llama.cpp) |
| **Reuse decision too loose / misses payload comparison** | silently reuses a graph with wrong semantics when cparams/LoRA change | parameter-deterministic decision (gtype/cparams/n_tokens/n_seqs/weights_version); `Op: PartialEq` full-payload comparison for a debug secondary check |
| **Backend interface host round trip** | per-node CPU↔GPU copies would be an order of magnitude slower | the Backend trait operates on buffer ids within the backend pool; cross-backend transfers only occur at split boundaries |
| **n_out optimization lost** | decode final layer computes extra rows beyond n_out | switch to the `GetRows(hidden, tail_ids)` row-selection node (same as llama.cpp `inp_out_ids`) |
| **Metal per-op dispatch overhead** | per-op independent submits may be slower than whole-layer submit | ops within a split share one command buffer, submit only at split boundaries; when a whole layer is fully GPU it can still take the `layer_gpu()` fast path |
| **Cross-backend KV copy** | per-step O(nkv) round trip when QKV is on GPU and attention is on CPU | scheduling policy: attention and KV cache forced to the same backend |
| **Double fusion** | fusion pass duplicates the existing fused kernel | fusion driven by `supports_fused`; GPU-side SwiGLU/BiasRope fused nodes connect directly to the existing kernel |
| **Performance regression** | graph build + scheduling has fixed overhead | parameter-deterministic reuse: decode topology unchanged, skipping rebuild and allocation |
| **GPU safety rules broken** | guard failures mistakenly treated as support fallback | preserve GPU_SAFETY.md semantics: device-limit class guards → `gpu_abort`; only support limitations such as Raw weights → fallback (determined at graph-build time) |
| **CUDA functionality regression** | existing CUDA Graph capture/replay lost | CudaBackend wraps cuda.rs and preserves CUDA Graph (uid key) |
| **DOT export increases code** | ~80 lines additional code | Feature-gated (`#[cfg(feature = "graph_dump")]`) |

### Record of Deviations from the Plan During Implementation

1. **`NodeMeta` uses a concrete enum instead of `Box<dyn Any + Send + Sync>`** (`src/graph/ops.rs`): supports `PartialEq` (for debug reuse checks), no downcast panic, `CNode` is `Clone`. Cost: adding a new metadata type requires changing the enum (already includes MatMul/Norm/Rope/Attn/Kvcache/Embed).
2. **`Op::Input` leaf node**: input nodes are marked with a dedicated op (corresponding to llama.cpp `GGML_OP_NONE` leaf); `ComputeGraph::inputs` records their ids.
3. **`rope()` adds a `style: RopeStyle` parameter** (the plan's example signature did not include it, but minfer `ModelDef::rope_style()` needs it); **`kvcache_store/load` explicitly carry `n_ctx`** for the persistent region's fixed length (load shape `[n_embd, n_ctx]`, at execution time only the written prefix is read).
4. **KV persistent region layout `[K | V]` contiguous** (one block per layer, length `2*n_embd*n_ctx`; guaranteed by the allocator since Phase 2, the attention kernel takes K and V from one buffer).
5. **`attn()` adds a `pos` input** (the plan's signature `attn(q, kv_layer, meta)` has no position——but the causal mask needs `pos[t]+1`; llama.cpp's mask likewise depends on the idx input).
6. **meta structure expansion**: `EmbedMeta.weight_name`, `RoPEMeta.n_head/hd`, `AttnMeta.nkt/scale` (required by the kernel, not listed in plan §3.1).
7. **`Backend::execute_node` takes `&mut self`** (the CPU pool needs mutable access; likewise for GPU backend command buffers); **single owner of the buffer pool = `GraphAllocator`** (the scheduler executes via the allocator, avoiding two pools).
8. **I32 inputs (token ids/positions) stored as `f32::from_bits` bit patterns** (exact for |v| < 2^24); the allocator provides `fill_input_i32`.
9. **F32 weight matmul supported on the CPU backend** (the existing `cpu_quant_matmul_f32` panics on F32; the graph path falls back through `vec_ops::mat_mul_f32`).
10. **BatchMatMul fusion deferred**: single-output IR (`CNode` has one out buffer) cannot express a multi-output fused node; IR expansion to be evaluated in Phase 5 (concat+view or multi-output nodes). SwiGLU/BiasRope fusion implemented and gated by backend `supports_fused`.
11. **single owner of the buffer pool = `GraphAllocator`** (final form of the Phase 2 deviation): the scheduler is a pure orchestrator (`assign_backends(graph, alloc)` queries allocator capabilities), execution goes through `alloc.cpu_mut()`. When the Metal pool was added in Phase 3, it is held in parallel within the allocator.
12. **`GraphParams` (`graph/params.rs`) is the entire basis for the reuse decision**: n_tokens/n_seqs/gtype/cparams/weights_version; `n_past` is explicitly absent (execution-time data). `weights_version` uses a global atomic counter, wired by the model in Phase 6.
13. **matmul weights use the llama.cpp/GGUF layout**: metadata `[in, out]` (ne[0]=in fastest), memory `[out][in]` row-major → `od = shape[1]`, `id = shape[0]` (the initial Phase 2 test version mistakenly used `[out, in]`, now fixed).
14. **KV persistent region survives graph rebuilds**: `GraphCache` owns the allocator; a rebuild swaps only the graph, not the KV region (KV is not lost when prefill→decode triggers a rebuild)——corresponding to llama.cpp's KV living in the memory context rather than the graph buffer.
15. **the scheduler executes in build order** (ggml-style `nodes[0..n]`), guaranteeing a KV store runs before the attention that reads it; orphan nodes produced by fusion (no consumers) are skipped.
16. **n_out tail-row optimization (GetRows) implemented (G3, `8febf4c`)**: the original "compute all nt, extract only the tail rows" has been replaced by the llama.cpp-style approach——insert `GetRows(wo/residual, tail_ids)` after the final layer's `wo` (`tail_ids` is an I32 input, prefill fills `[(nt-n_out)..nt)`; when decode nt==1 and n_out==nt no node is built); the final-layer FFN + output_norm + lm_head all run only on the tail `n_out` rows; `GraphParams.n_out` participates in the reuse decision (`cache::params_match`). 0.5B prefill pp440 ~3900-4000 t/s (+~55% vs old path; ~2600 after G1/G2).
17. **forward.rs deleted in Phase 6** (`6af12a4`): deleted after bit-identical logits verification passed; `embed_tokens` moved into `kernel.rs`; `--graph` kept as a compatibility no-op (the graph path is already the default).
18. **in-place op buffer aliasing** (key Phase 3 fix): the output buffer of `Silu`/`RoPE` **aliases** the input buffer (when same backend and the input's sole consumer)——avoiding a host-side copy reading not-yet-written GPU data under batching (single command buffer) (this bug once caused the KV region to be all 0 and garbled output; after the fix 437 nodes on a single cb are correct). Cross-backend inputs still get a distinct buffer (the producer is already complete, so the copy there is safe).
19. **backend configuration enters the reuse decision**: the `CParams.gpu` flag——backend assignment is part of graph construction; MPS initialization changes (e.g. between tests) must trigger a rebuild.
20. **each layer's KV = two independent persistent regions (k, v)** (finalized in Phase 3, replacing Phase 1's [K|V] contiguous layout): symmetric on CPU/Metal; attention gets the sibling region via `kv_pair(layer)`.
21. **MetalBackend wiring optimization G1/G2 (`32b0d03`)**: `Attn` dispatches by nt/hd to flash/split/parallel/classic (gating consistent with the old path: `flash_attn_enabled(hd)`, `prefill_flash_enabled(hd)`, `matmul_attn_enabled()`, `MINFER_NO_*`, `MINFER_ATTN_CHUNKS`); `RmsNorm` uses `rms_norm_256` (when `rms_norm_256_enabled()`). Pure wiring; the kernels were already isolated-tested.
22. **allocator liveness must be consistent with the scheduler's execution order (G3 fix, `8febf4c`)**: the scheduler executes in build order (node id order), whereas the allocator originally used `topo_order()` (Kahn) for liveness——Kahn would move srcless nodes like `kv_load` ahead, making liveness think an input is dead and its buffer reusable by a later node, while the scheduler has not actually read it yet (G3 tail-shrink graph: attn reused residual h's buffer, so `get_rows(h)` read the attn output instead, logits differ by 21.79). Fix: the allocator uses build order for liveness (`topo_order` only for cycle checking).
23. **input buffers are never freed (G3 fix, `8febf4c`)**: all inputs are host-filled before execute; if two inputs' buffers are reused as the same block by liveness, the later-filled one overwrites the earlier (the `embedding_and_rope` regression: token_ids overwritten by positions). Fix: inputs get the same treatment as outputs (`last_use = order.len()`).
24. **G1-G3 measured (M4 Pro, `--temp 0` greedy)**: 0.5B decode KV206 ~122 → **~256 t/s** (2.1×, ≈ old path); 0.5B prefill pp440 **~3900-4000 t/s** (+~55% vs old path 2530-2620); 7B decode KV206 ~32.5 → **~49 t/s** (≈ old path ~48); 7B prefill pp206 ~217 t/s (≈ old path ~240, −10%, attention not the bottleneck). Greedy output per-token identical to pre-G1 (flash/split/parallel numerically identical to classic; tail-shrink graph logits bit-identical to the full-nt graph).
25. **FusedQKV (G4, `a2c83bc`)**: during decode (nt==1) build generates a single `Op::FusedQKV{layer}` node——Metal-side 1 concat matmul (reusing the loader-registered `blk.{i}.attn_qkv`, wq/wk/wv rows concatenated) + 1 `attn_bias_rope_store` (same as llama `kernel_attn_bias_rope_store`: 3 bias + q/k rope + K/V store in one pass); attn reads q from concat buffer offset 0 (nt==1 no stride issue). Deviation: `attn()` output shape now determined by `AttnMeta` (n_head*hd) rather than the q input shape (fused q is a larger concat buffer); `CParams` adds `fuse_qkv` (env `MINFER_NO_FUSE_QKV=1` disables; part of the reuse decision, so A/B-able); the CPU side does not support FusedQKV (the CPU graph does not build it).
26. **FusedFFN (G5, `d7206f0`)**: during decode (nt==1) build generates a single `Op::FusedFFN` node——1 concat matmul (`blk.{i}.ffn_gu`, ffn_gate/ffn_up rows concatenated, loader-registered) + 1 in-place `swiglu_f32_off` (same kernel `kernel_swiglu_f32` as the `Op::SwiGLU` folded by the fusion pass on the unfused path, only up uses a set_buffer offset → bit-identical); the down matmul reads concat rows 0..nf (od=nf, safe for nt==1 layout). **Gated `nf ≤ 16384`**: the 7B Q4_K concat matmul (od≈37888) measured slower than two separate matmuls on the decode nt==1 scalar kernel (42.5 vs 46.7 t/s); 0.5B Q4_0 is ~3% faster (312-331 vs 303). Debugging lesson: in a test, if an unfused graph does not run FusionPass, silu+mul executing as two kernels differs from a single swiglu kernel by ~1e-6 float noise (amplified at large values)——the real forward path always runs FusionPass, and the two paths are bit-identical.
5. Full-suite test baseline: `cargo test --release` = 46 pass / 1 fail (`attn_parallel_realdata_correctness` needs the real dump `minfer_gpu_dump_layer0_b{q,k,v}.f32` under `/tmp/dp3`, a pre-existing environment-dependent failure).
