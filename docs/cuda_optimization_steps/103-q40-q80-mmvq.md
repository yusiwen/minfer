# 103 · q4_0 / q8_0 decode joins the MMVQ family — q4_0 decode now beats llama.cpp; spec on q8_0 models doubles

**Status**: ✅ landed (2026-09-15). The 8e MMVQ structure (dp4a over the
shared pad40 q8 activation plane, one row per 256-thread block) extended to
the two legacy f32-activation types, with multi-token (nt 2–8) variants for
the doc-95 verify batch. **New code only** — every landed kernel and dispatch
arm (q4_K/q5_K/q6_K MMVQ, raw-BT, the 8c q4_0 prefill branch) is untouched;
the new branches claim only shapes that previously ran the unoptimized f32
kernels, with `MINFER_NO_Q40_MMVQ=1` / `MINFER_NO_Q80_MMVQ=1` fallbacks.

## 3. Implementation notes

- Kernels: `q4_0_q8_mmvq(_multi)`, `q8_0_q8_mmvq(_multi)` in
  `cuda_kernels.cu` — the q4_K MMVQ structure with per-type block decode.
  Block strides are 18 B / 34 B: even but not 4-aligned, so weight payload
  reads use the q6_K two-u16-half pattern. The q4_0 nibble offset (−8 per
  element) is folded into the dot via `dot − 8·sx` (sx = Σx by dp4a), keeping
  every product in exact int32 until one final float multiply — the same
  accumulation order in the nt = 1 and multi kernels (bitwise-consistent,
  which is what the doc 93/94 identity contract requires of the verify batch
  vs sequential decode).
- Dispatch (`src/cuda.rs`): nt = 1 engages at `id ≥ 2048 && id % 32 == 0`
  (the 8e gate); multi engages at nt 2–8 with the same floor for q8_0 and
  `id > 8192` for q4_0 — above the 8c int8-prefill branch's territory, which
  stays exactly as landed. Everything else falls through to the f32 kernels
  verbatim.
- `decode_quantize_native` (the shared pad40 q8 activation plane, MmqCache
  fuse included) is reused as-is.
